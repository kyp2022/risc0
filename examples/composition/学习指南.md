# Composition 示例学习指南

## 📚 学习路径

### 第一步：理解 RISC Zero 基础概念

在理解 Composition 之前，你需要先掌握以下核心概念：

#### 1. **zkVM 基本架构**
- **Host（主机）**：运行在普通环境中的程序，负责准备数据、调用证明者、验证 receipt
- **Guest（客机）**：运行在 zkVM 中的程序，执行需要证明的计算
- **Receipt（收据）**：证明某个计算正确执行的密码学证明

#### 2. **基本工作流程**
```
Host 准备数据 → Guest 执行计算 → 生成 Receipt → 验证 Receipt
```

#### 3. **关键 API**
- `env::read()`：Guest 从 Host 读取数据
- `env::commit()`：Guest 将结果提交到 journal（公开输出）
- `receipt.verify()`：验证 receipt 的有效性

### 第三步：理解 Composition 的核心概念

#### 什么是 Composition（证明组合）？

**简单理解**：在一个 Guest 程序中验证另一个 Guest 程序的 Receipt，然后将两个证明组合成一个 Receipt。

**类比**：
- 就像数学证明中的"引理"：先证明引理 A，然后在证明定理 B 时使用引理 A
- 最终得到一个证明，它同时证明了 A 和 B

#### 为什么需要 Composition？

1. **模块化**：将复杂计算拆分为多个简单计算
2. **隐私保护**：不同方可以各自证明自己的部分
3. **效率提升**：批量验证多个证明
4. **工作流组合**：将多个步骤组合成单一证明

### 第四步：深入理解 Composition 示例

#### 示例场景：模拟 RSA 加密

**角色设定**：
- **Alice**：生成 RSA 密钥对（知道 n 的因式分解）
- **Bob**：使用 Alice 的公钥加密消息

**流程**：

```
步骤 1: Alice 生成密钥
├─ 选择两个质数：17 和 23
├─ 计算乘积：n = 17 × 23 = 391
└─ 生成 Receipt₁：证明"我知道 391 的因式分解"

步骤 2: Bob 加密消息
├─ 接收：n（公钥模数）和 Receipt₁
├─ 选择：e = 9（公开指数），x = 100（秘密消息）
├─ 在 Guest 中：
│   ├─ 验证 Receipt₁（证明 n 有已知因式分解）
│   └─ 计算 c = x^e mod n = 100^9 mod 391
└─ 生成 Receipt₂：证明"c 是正确的加密结果，且 n 有已知因式分解"
```

#### 代码执行流程

**Host 端（`src/main.rs`）**：

```rust
// 1. Alice 生成第一个证明（调用 hello-world 的 multiply）
let (multiply_receipt, n) = multiply(17, 23);
// multiply_receipt: 证明 n=391 有已知因式分解
// n: 391

// 2. 准备执行环境，添加 assumption（假设）
let env = ExecutorEnv::builder()
    .add_assumption(multiply_receipt)  // ← 关键：将 receipt 添加到环境
    .write(&(n, 9u64, 100u64))         // 写入 (n, e, x)
    .build()
    .unwrap();

// 3. 执行 Guest 程序，生成组合证明
let receipt = default_prover()
    .prove(env, EXPONENTIATE_ELF)
    .unwrap()
    .receipt;

// 4. 验证最终 receipt（同时验证了两个证明）
receipt.verify(EXPONENTIATE_ID).unwrap();
```

**Guest 端（`methods/guest/src/main.rs`）**：

```rust
// 1. 读取输入
let (n, e, x): (u64, u64, u64) = env::read();
// n = 391, e = 9, x = 100

// 2. 验证之前的 receipt（关键步骤！）
env::verify(MULTIPLY_ID, &serde::to_vec(&n).unwrap()).unwrap();
// 这验证了 multiply_receipt，证明 n 有已知因式分解

// 3. 计算模幂运算
let c = pow_mod(x, e, n);  // c = 100^9 mod 391

// 4. 提交结果
env::commit(&(n, e, c));
```

### 第五步：关键 API 详解

#### 1. `add_assumption(receipt)`

**位置**：Host 端，`ExecutorEnv::builder()`

**作用**：将需要验证的 receipt 添加到执行环境中，使得 Guest 程序可以通过 `env::verify()` 验证它。

**类比**：就像给 Guest 程序提供"证据"，让它可以在自己的证明中引用这个证据。

#### 2. `env::verify(image_id, journal_data)`

**位置**：Guest 端

**参数**：
- `image_id`：要验证的 Guest 程序的 ID（如 `MULTIPLY_ID`）
- `journal_data`：要验证的 journal 数据（序列化后的值）

**作用**：验证一个 receipt，确保它对应的 Guest 程序确实产生了指定的 journal 数据。

**在本示例中**：
```rust
env::verify(MULTIPLY_ID, &serde::to_vec(&n).unwrap())
```
这行代码验证了：
- 存在一个有效的 multiply receipt
- 该 receipt 的 journal 中包含 n（391）
- 因此，n 确实有已知的因式分解

#### 3. `pow_mod(x, e, n)` - 快速幂算法

**算法原理**：将指数 e 表示为二进制，通过平方和乘法组合计算。

**示例**：计算 100^9 mod 391
```
9 = 1001₂ (二进制)
100^9 = 100^(8+1) = 100^8 × 100^1
```

**算法步骤**：
```
初始化：z = 1, x = 100, e = 9

e = 9 (奇数) → z = (1 × 100) mod 391 = 100
              x = (100 × 100) mod 391 = 10000 mod 391 = 209
              e = 4

e = 4 (偶数) → z = 100 (不变)
              x = (209 × 209) mod 391 = ...
              e = 2

...继续直到 e = 0
```

### 常见问题

#### Q1: 为什么需要 `add_assumption()`？

**A**: Guest 程序无法直接访问外部的 receipt。`add_assumption()` 将 receipt 添加到执行环境中，使得 Guest 可以通过 `env::verify()` 验证它。

#### Q2: `env::verify()` 会执行原来的 Guest 程序吗？

**A**: 不会。它只是验证 receipt 的有效性，不会重新执行计算。这是零知识证明的核心：验证证明比重新计算快得多。

#### Q3: 最终的 receipt 大小是多少？

**A**: 组合后的 receipt 包含了两个证明的信息，但通过密码学技术，它的大小不会是两个 receipt 的简单相加。

#### Q4: 可以组合多个 receipt 吗？

**A**: 可以！你可以多次调用 `add_assumption()` 添加多个 receipt，然后在 Guest 中多次调用 `env::verify()`。

### 总结

**Composition 的核心思想**：
1. 将复杂问题分解为简单问题
2. 每个简单问题生成独立的 proof
3. 在后续证明中验证之前的 proof
4. 最终得到一个组合 proof，证明所有步骤

**实际应用**：
- 多方计算：不同方各自证明，然后组合
- 工作流验证：将多个步骤组合成单一证明
- 批量验证：提高验证效率
